## 1. Latency 벤치마크

각 시나리오 baseline 3회, ko+en 필터 3회 median.

### 최적화 후 (v2 — GPU 텐서 사전 할당)

| 시나리오 | max_tokens | baseline | ko+en | overhead | 생성 토큰(B/F) |
|----------|-----------|----------|-------|----------|--------------|
| Short | 20 | 0.141s | 0.138s | -2.4% | 13/13 |
| Medium | 80 | 0.732s | 0.729s | -0.5% | 80/80 |
| Long | 200 | 1.786s | 1.788s | +0.1% | 200/200 |
| English | 80 | 0.731s | 0.731s | +0.0% | 80/80 |
| Code | 150 | 1.347s | 1.347s | +0.0% | 150/150 |
| JSON | 80 | 0.181s | 0.179s | -1.0% | 18/18 |
| Multi-turn | 80 | 0.727s | 0.727s | -0.1% | 80/80 |

**종합: overhead 0% (측정 오차 범위 내)**

### 최적화 전 (v1 — 참고)

| 시나리오 | max_tokens | baseline | ko+en | overhead |
|----------|-----------|----------|-------|----------|
| Short | 20 | 0.141s | 0.172s | +22.3% |
| Medium | 80 | 0.726s | 0.881s | +21.3% |
| Long | 200 | 1.785s | 2.210s | +23.8% |

v1은 `apply()` 내에서 매 디코드 스텝마다 `torch.tensor(indices, device=cuda)` 등
CPU→GPU 텐서 할당+전송이 발생해 per-token ~2ms 오버헤드가 있었음.

### 최적화 내용

1. `update_state()`에서 GPU 텐서(`rows`, `last_tok_gpu`) 사전 할당 — 배치 변경 시에만 재생성
2. byte guard용 CPU 버퍼를 pinned memory로 사전 할당 — `apply()`에서 재사용
3. byte guard 실행 전 CPU 측 확인 — regulated lead byte가 아니면 GPU 전송 자체 스킵
4. combo_groups를 `update_state()`에서 미리 계산 — `apply()`에서 Python dict 생성 제거
5. `changed` 플래그로 배치 변경 없으면 `_rebuild()` 스킵

## 7. 알려진 사항

### 한자 처리
- ko에서 한자 제거됨. "한자를 써줘" 요청 시 한글 표기로 대체
- 한자가 필요하면 `["ko", "ja"]` 또는 `["ko", "zh"]` 조합 사용

### Latency overhead
- 최적화 후: **overhead 0%** (측정 오차 범위 내)
- `apply()`에서 CPU→GPU 텐서 전송 완전 제거
- GPU 텐서는 `update_state()`에서 사전 할당, `apply()`에서 재사용
- byte guard는 regulated lead byte가 아닌 경우 GPU 전송 자체 스킵
- 혼합 배치에서 필터 없는 요청에 영향 없음 (`if not self._active: return logits` 즉시 반환)

### 외국어 유도 시 동작
- 모델이 외국 문자를 못 쓰면 로마자 음차 또는 한글 발음으로 자동 대체
- 정보 손실 없음, 가독성은 약간 떨어질 수 있음
- 이는 의도한 동작 — 스크립트 혼입 방지가 목적

### vLLM 호환성
- `LogitsProcessor.__init__`에서 `super().__init__()` 호출 금지 (vLLM 0.28 base class가 NotImplementedError raise)
- vLLM 0.26(실서빙)에서 별도 확인 필요
